# Cognitive Razor 当前代码设计

日期：2026-09-28

性质：这是对插件源码的观察，不是需求。需求基线在 [REQUIREMENTS.md](REQUIREMENTS.md)。某项行为写在这里，只说明代码现在这样做。

证据来自 `obsidian-cognitive-razor` 的源码、提示词和既有记录。本文没有重跑测试，也没有在运行中的 Obsidian 里重载插件。2026-09-27 的自动测试范围仍以 `progress.md` 为准。当时记录是 62 个测试文件、552 项测试通过，且没有真实 Provider 请求、没有 Decks 运行时解析。

## 插件在运行时如何分成几块

Obsidian 入口是 `main.ts` 的 `CognitiveRazorPlugin`。设置和命令在加载时就可用。会读写库、跑队列或访问网络的服务，要等打开工作台或执行操作时，才由 `PluginRuntime` 创建。

`PluginRuntime` 组装这些部分：

| 部分 | 代码 | 做什么 |
| --- | --- | --- |
| 设置 | `SettingsStore`、`SettingsApplication` | 读写 `data.json`，迁移缺字段的旧设置 |
| 笔记 | `NoteRepository`、`CruidCache` | 按路径读写 Markdown，维护 `cruid` |
| 模型 | `ProviderManager`、`TaskRunner` | 按任务类型取模型快照并发起请求 |
| 提示词 | `PromptManager`、`prompts/` | 从插件目录加载固定模板 |
| 创建 / 核查 / 拓展 | `CreateOrchestrator`、`VerifyOrchestrator`、`ExpandOrchestrator`、`WorkflowCoordinator` | 用户确认后的持久工作流 |
| 卡片 | `CardGenerationService`、`CardsTaskExecutor` | 独立于创建阶段的追加任务 |
| 队列 | `TaskQueue` | 调度、取消、恢复；状态在 `data/queue-state-v5.json`，版本号 `8.0.0` |
| 索引与重复 | `VectorIndex`、`SemanticIndexRebuilder`、`DuplicateManager`、`DuplicateMergeService` | 向量、重复候选、合并 |
| 工作台 | `WorkbenchApplication` 与 Svelte 界面 | 只发命令和读状态，不拥有队列 |

外部调用账本 `InMemoryExternalCallLedger` 只在当前进程里。重载后不能用它证明某次请求是否已经计费。

## 用户能看见的流程

工作台三块：创建、队列、重复对。命令有「打开工作台」和「事实核查」。

### 定义并创建节点

创建区输入一句话后，`defineDirect` 立刻请求 Define 模型，返回五类候选和一条核心定义。这一步不入队，也不写笔记。

你点选类型后，`confirmDefinePreview` 做成已确认概念，`WorkflowCoordinator.startCreate` 才创建文件。目标路径由类型目录加名称决定。同路径已有笔记或已有活动任务时拒绝，不覆盖。

新笔记 frontmatter 含 `cruid`、`type`、`name`、`parents`、`aliases`、`tags`、`created`、`updated`。创建草稿的状态是 `seed`。标签阶段成功后变为 `draft`。

随后自动入队的顺序是：标签，然后该类型的写作阶段。写作阶段由 `stage-catalog.ts` 固定：

| 类型 | 写作阶段与字段 |
| --- | --- |
| 领域 | 核心（定义、核心问题、方法、边界）→ 叙事 → 结构（子领域、议题） |
| 议题 | 核心 → 叙事 → 结构（子议题、相关方、理论） |
| 理论 | 核心 → 叙事 → 结构（子理论、实体、机制） |
| 实体 | 核心 → 综合 |
| 机制 | 核心 → 过程 → 综合 |

Verify 不在这条自动链上，除非创建确认的那一刻设置里的「自动事实核查」是开的。该开关默认关，并且写进当次工作流记录，之后改设置不影响已经开始的工作流。

### 拓展

按钮在打开任意 Markdown 时都显示。真正执行时要求合法的 Cognitive Razor frontmatter，且 `type`、`status` 必须是小写规范值，插件不改写旧笔记。

- 领域、议题、理论：从正文章节解析下位候选，你勾选后逐个走创建确认。单次可创建上限 200。
- 实体、机制：先按向量找相似节点，再生成更高层概念的预览，你确认后才创建。

层级拓展会把当前笔记名称写成父链接。

### 事实核查

工作台按钮和命令都可以启动。`startVerify` 要求目标是已有的 Cognitive Razor 笔记，并捕获当时全文。核查任务单独成一个 `verify` 工作流，不接着跑写作阶段。

成功提交时，用标记块替换核查报告，并把状态写成 `evergreen`。若提交时笔记内容已经和启动快照不同，拒绝覆盖，并留下快照冲突恢复记录。

核查可以使用搜索和对话续写。卡片任务不带这些上下文。

### 记忆卡片

按钮只在当前文件能解析出 Cognitive Razor frontmatter 时显示。

`captureCardInput` 在入队时做这些事：

- 源路径必须落在设置的知识库根目录下，且是 `.md`。
- 去掉 YAML，再用 `stripVerifyReport` 去掉核查报告。普通标题保留。正文不按 12,000 字截断；截断只存在于 `buildSemanticIndexText`。
- 目标路径是习题库根目录下的镜像相对路径，文件名改为 `-decks.md`。目标不能等于源路径。
- 快照、节点 id、名称、类型和提示词版本 `cards-v1` 写入 `data/cards/<id>.json`。队列记录只保存调度信息，并通过这个 id 找回快照。

同一路径已有等待中或执行中的卡片任务时，拒绝再入队。

`CardsTaskExecutor` 只用 `taskModels.cards` 的快照和 `prompts/base/operations/cards.md`。请求体是正文快照，不附带 JSON schema、搜索或 Verify 历史。返回后拒绝：空文本、整个结果是 JSON 对象、以 HTML 开头、或以代码围栏开头。通过后才进入追加。

`NoteRepository.appendCards`：

- 目标文件已存在：在当前文件末尾追加本批 Markdown，不改已有字节。
- 目标文件不存在：先建缺失目录，再写入带 `tags: [decks]` 的新文件和本批正文。
- 不去重，不加批次标题，不打开目标文件。

追加前先把生成记录标成 `committing` 并写下整批 Markdown。追加成功后再标 `completed`。卡片任务禁止从旧记录重试；失败或中断后只能从源笔记重新生成。清理队列历史时，才会删除对应的 `data/cards` 记录。

### 重复与合并

语义索引默认开启，重复检测默认开启，相似度阈值默认 0.85。达到阈值的配对出现在工作台。你可以忽略，或选择保留的主笔记、编辑合并稿，确认后写入主笔记并把另一份移入回收站。回收站之前会先记下恢复意图，避免重启后重复丢弃。

同名不同类型不会仅因名称相同就被当成重复。重复判断走的是向量相似度，不是名称相等。

### 设置

三个页：AI 服务、工作流、备份与重置。

工作流页包含：五类目录、自动事实核查、卡片的两个根目录（默认 `C-知识库`、`D-习题库`）、七种任务模型（define、tag、write、index、verify、merge、cards）。Cards 的 Provider 和模型必须单独填写，旧设置缺这个字段时填空。

语义索引维护默认折叠，其中包括指定笔记路径的向量重建、全库重建、补嵌入、向量文件清理和重复对重建。工作台源码不再调用 `rebuildCurrentNote`。

队列默认同时只跑 1 个任务。任务超时默认 3 分钟。Provider 超时默认 60 秒，每个网络阶段最多 3 次尝试，含第一次。结果未知（超时、408、502、503、504、连接或流式中断）不自动重试。HTTP 500 的明确失败仍按既有策略重试。

## 持久化与恢复

| 数据 | 位置 | 角色 |
| --- | --- | --- |
| 插件设置 | `data.json` | Provider、模型、目录、开关 |
| 队列 | `data/queue-state-v5.json` | 调度状态，不是完整业务结果 |
| 创建 / 核查 | Workflow artifact，版本 `7.0.0` | 阶段输入、已应用阶段、待提交结果 |
| 卡片 | `data/cards/*.json` | 正文快照、目标路径、整批结果 |
| 日志 | `data/app.log` | 诊断 |

重载时：

- 能只靠本地已保存结果完成的阶段，可以不发新请求而提交。
- 不能这样恢复的 `running` 任务变成 `interrupted`，并写明结果未知、不自动重试。
- 旧的 `failed` 且 `kind: uncertain` 在加载时迁成 `interrupted`。
- 未知阶段的记录保留，但不执行，并阻止它所属工作流自动补发下一阶段。
- 更早的不兼容队列文件隔离，不猜测迁移。
- 单个损坏的工作流记录不会清空整个队列。

取消：请求还没进入提交时可以取消。若请求可能已经发出，本地停止等待，并把任务标为已中断，不自动重试。提交已经开始后，队列拒绝取消，不能保证撤回已经写出的文件。

卡片的崩溃窗口：追加已经发生、完成状态还没落盘时，文件里可能已有本批内容。恢复不会再追加一次，也不能把已写入的内容撤销。若停在 `committing` 且追加没发生，恢复同样不会自动补写，需要你重新生成。

创建和核查在改笔记前会对照启动时或上一阶段确认过的快照。外部改过的笔记不会被静默覆盖。

## 和已确认需求的对照

状态只相对于 [REQUIREMENTS.md](REQUIREMENTS.md)。「符合」表示当前源码行为与该条一致。「差距」表示确认过的要求在代码里没有落实，或落实方式和记录不一致。「超出」表示代码有行为，但该条需求没有要求它。

| 需求 | 状态 | 代码里的实际情况 |
| --- | --- | --- |
| R1 三个入口 | 符合 | 创建区有拓展、事实核查；节点另有生成记忆卡片 |
| R2 卡片只对节点 | 符合 | 非节点不显示按钮；入队时没有合法 frontmatter 会拒绝 |
| R3 卡片不看核查状态 | 符合 | 卡片启动不读取 Verify 是否完成 |
| R4 向量重建离开工作台 | 符合 | 指定路径重建在工作流设置的语义索引区。工作台应用层仍留有 `rebuildCurrentNote`，界面不调用 |
| R5 五类本体 | 符合 | `CR_TYPES` 固定这五类。没有「暂不分类」的持久类型 |
| R6 同名不同类型 | 符合 | 路径含类型目录，同名可落在不同目录。重复检测不按同名合并 |
| R7 先确认类型再创建 | 符合 | Define 只产预览；`startCreate` 拒绝未经确认的概念 |
| R8 顺序 Define → Tag → Write → Verify | 部分符合 | Define 在确认前同步完成。确认后自动是 Tag 和写作阶段。Verify 默认要另按按钮，除非当次创建记下了自动核查 |
| R9 不因卡片改变 Verify | 符合 | 卡片不写入 `appliedStageIds`，也不给核查加新闸门 |
| R9 的完成门槛 | 未决被实现成具体行为 | 核查提交成功时把 `status` 写成 `evergreen`。这不是需求记录里确认过的门槛 |
| R10–R12 理解型卡片与混用格式 | 符合提示词 | 规则在 `prompts/base/operations/cards.md`。代码不限制张数，也不做格式打分 |
| R11 技术边界要可见 | 部分符合 | 超时和尝试次数存在于设置与错误码。卡片按钮本身不提前提示 token 或超时上限 |
| R13–R14 追加、镜像、默认根目录 | 符合 | `appendCards` 与 `captureCardInput` |
| R15 全文正文、去掉报告、不截断 | 符合 | 向量文本仍截断到 12,000 字；卡片路径不调用该函数 |
| R16 入队锁定快照和目标 | 符合 | 之后改源笔记或根目录，不回写已保存的 `input` |
| R17 整批成功后追加、不预览 | 符合 | 与宪章「先预览再接受」不一致。按需求基线，这是你确认过的收窄，不是实现漏做 |
| R18 不做格式修复式拒绝 | 符合 | 只拒绝空、JSON 对象、HTML 和整段围栏。不解析 Decks 结构 |
| R19 独立任务 | 符合 | `stage-catalog` 的创建阶段列表不含 cards |
| R20 推演情境必须标明 | 符合提示词 | 代码不二次检查模型有没有写上这两个词 |
| R21–R22 独立模型、固定提示词 | 符合 | 未填 Provider 或模型返回 `E401`，界面提示去工作流设置。设置页没有卡片提示词编辑器 |
| R23–R25 中断不追加、不自动重试 | 符合 | `interrupted` 是独立状态。卡片 `beforeRetry` 直接拒绝重放 |
| R26 写入失败不另做无请求重放 | 符合 | 追加失败返回错误。`committing` 记录不会在重启后续写 |

## 代码有、需求未确认的设计

这些是实现事实，验收时不要当成你已经要求过：

- 笔记状态机是 `seed` → `draft` → 核查后的 `evergreen`。类型里还有这三态，但没有单独的「待验证」字段密度统计。
- 写作提示词由知识政策、文风、反模式、输出格式和阶段模板拼成。卡片模板不拼这四块基础组件，只用自己的 `cards.md`。
- 标签写 aliases 和 tags。写作把模型 JSON 渲染成 Markdown 正文。这些字段表是目录里的契约，不是 2026-09-21 那份确认里逐项点过的。
- 重复合并在确认前有预览，确认后进回收站。这比卡片更接近宪章的可逆要求，但是否是你要的产品行为，记录里没有单独确认。
- 创建完成且运行时挂了索引回调时，会尝试给新节点做向量。失败只记日志，不让工作流失败。
- Provider 账本不跨重启。不能用插件数据证明「没有重复扣费」，只能证明进程内的尝试次数和「不确定则不自动重试」这条策略。

## 还不能当成已经验收的部分

- 当前 Vault 在 2026-09-27 的记录里没有 Decks 插件。标题卡、表格卡、cloze 和混合文件是否被 Decks 识别，只对照过上游 README，没有运行时结果。
- 同一记录里 Obsidian CLI 找不到正在运行的 Obsidian，因此那一轮没有重载插件，也没有真实模型请求。
- 卡片追加使用 `vault.process` / `vault.create`。自动化测试覆盖了首次创建、重复追加和保留手工内容。宿主里的文件监听、同步冲突和 Decks 刷新不在该测试里。
