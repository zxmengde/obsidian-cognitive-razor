# 提示词与缓存

## v1 规则

默认提示词由 `prompts/` 中 22 个文件组成。公共知识政策规定来源、适用条件、名称与证据边界；写作规则规定解释深度和行文；输出规则规定 JSON、Markdown 和美元公式定界符。Define、Tag、Verify、Merge、Cards 各有任务规则，五类知识使用 14 份阶段模板。

生产提示词只包含通用、明确的规则，不包含示例。输入、正文、对话和来源区块是数据，不授予改写任务规则的权限。缺乏依据时保留不确定性，必填字段不授权编造。

命名保持对象的指称与范围，优先通行中英文名称，同一对象在字段和分类组间保持一致；正式复合名称保持完整。别名包括中文标准名、英文标准名及有区别的繁体字形。自拟标题遵循公共长度与格式规则，固定标题按对应阶段输出。

层级分类只列直属下一层。每套分类保持同一依据、关系和相当粒度，以覆盖父项范围为目标，证据不足时说明已知范围。适用标准的划分依据或归属规则不同时分别分组，同依据同归属的异名体系合并；跨组交叉保留并说明。应用目标形成的通行领域可以列入；活动、研发阶段与流程本身不作为子领域。实体分类和核查使用一致的分类边界。

Verify 的公式使用单个美元符号包围行内公式，独立公式使用双美元符号且起止符各占一行。公式内部的括号、方括号保留其数学含义。

## 组装与版本身份

`PromptManager` 从插件内模板加载规则。共享写作规则位于系统部分，阶段任务及动态材料位于后部。`schema-registry.ts` 定义字段契约，`stage-catalog.ts` 定义阶段；模板不复制整份字段表。

写作与核查的提示词身份为 `v1`，卡片身份为 `cards-v1`。身份用于缓存路由及判断对话是否可重放。服务、模型、协议、端点、能力或提示词身份不匹配时，保留已有草稿，使用当前规则重新组装请求。

发行包提供完整默认模板。模板文件可由使用者定制；覆盖前先备份并比较差异。

## 默认隐式缓存

Responses 写作保持系统指令、Schema、工具和累积消息前缀稳定；Gemini 写作保持对应 contents 前缀及类型 Schema 稳定。阶段材料放在可复用内容之后，避免动态信息提前破坏公共前缀。搜索能力与模型参数在同一工作流中固定。

缓存是服务端行为。前缀稳定、长度满足服务要求时具备复用条件，插件不能保证每次命中；省略统计字段表示未报告。Responses 的 cached_tokens 与 Gemini 的 cachedContentTokenCount 只在服务实际返回时用于记录。显式缓存路由与响应 ID 续接属于单独配置，不构成 Gemini 默认隐式缓存的开关。

## 离线检查

[完整检查稿](../prompt-examples.md)包含两个合成配置各 25 项完整请求，覆盖所有写作阶段及定义、标签、核查、合并、卡片。夹具正文、历史和来源均为测试数据；生产提示词不包含这些示例。

`scripts/generate-prompts.mjs` 经生产执行器及 ProviderManager 截获请求，命令为 `npm run prompts:generate -- --settings <合成配置文件> --output <输出目录>`。导出使用明确传入的配置，不读取日常库设置，不发送模型请求。检查原始请求、展开文本、Schema、工具、参数与哈希；真实模型质量和缓存命中另行验收。
