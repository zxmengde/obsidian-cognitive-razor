# 合并质量实测

2026-10-26，在五类合成材料中复现了固定章节被改名或合并、旧核查报告被写进知识正文的问题。当前请求提供类型章节顺序并剔除插件核查块，提示词要求完整整合、同义去重及正文内保留未决分歧。优化后的六份草稿和两个重复结果均保留已有固定标题、来源链接与输入元数据；未发现所列关键事实和条件的遗漏。此结论限于本轮短篇材料，不代表通用质量通过率。

## 材料与方法

[merge_quality.json](../evals/merge_quality.json) 包含五类型案例及一份留出材料，全部是明确标注的合成教学数据，不含私人笔记。输入配有预先固定的检查点；`expected` 不发给模型。评阅由开发代理逐项对照输入完成，不是独立人工评审或另一个模型的评分。固定标题、顺序、内部链接和元数据并集另做机械检查，不能用这些检查代替语义评阅。

真实服务为用户授权的 `http://39.105.206.63:8317/v1`，Responses API，`gpt-6.1-sol`，high 思考等级。请求与返回模型字段一致。全部走生产请求组装、Node HTTP 流传输、解析和合并执行器；模型阶段的 Obsidian 宿主替代为测试边界。没有搜索、重试、回退模型或指定种子。共 14 次请求：五类前后各一次，留出前后各一次，实体和机制优化后各重复一次。

留出基线在改动前生成，输出直到生产规则冻结后才评阅；未据留出结果继续调整规则。此前的核查、制卡及数据保护测试不计入本轮请求数。服务端报告输入 25,876、输出 10,163，合计 36,039 tokens，其中缓存读取 3,456；不是计费证明。

## 代码与验收

实际修改仅涉及合并送模投影和通用成文规则；章节取自现有 Schema，复用现有核查块过滤函数，没有新增五套静态模板、语义重试或输出回退。单元测试先复现报告进入模型请求，再验证其剔除、原确认快照完整和提交仍成功；另覆盖五类型标题与理论“前提”的实际请求数据。

取舍：核查报告是单独的诊断投影，核查流程并不直接修订正文。本轮以两篇知识正文为合并依据，所有插件核查块都从送模内容剔除，避免旧记录变成知识；原始报告仍可在确认预览的原文快照中查看。报告中尚未落实的纠错建议不会自动应用到合并稿，应先修正文或在确认草稿时处理。这一边界没有被本轮“主要事实保留”的结论覆盖。

真实 Obsidian 1.14.5（installer 1.14.4）中，在 `C:/code/obsidian` 的限定测试笔记上重放六份优化草稿。六案的主笔记写入、类型保留、核查块排除、正文和父项链接修复、代码中链接保留、冗余笔记进入回收站及恢复记录收尾均通过；共 54 个宿主断言。证据见 [merge_quality_host_results.json](../evals/merge_quality_host_results.json)。使用真实 Vault 和文件持久化，但候选映射、队列和重建索引回调受控；没有声称原工作台全链路或真实嵌入已通过。

相关合并、笔记原子写入、草稿服务、链接界面、错误反馈及提示词测试通过；`check:test`、lint、宿主工具严格类型检查、构建通过。完整检查稿从生产边界重新离线截获两配置共 50 份请求，保持 v1，不调用模型。
