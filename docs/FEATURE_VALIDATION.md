# 核查、合并与制卡实测

结论：GPT-6.1 Sol 在小型技术材料上的核查、合并草稿与制卡结果符合主要预期；**合并提交的数据保护已修复并通过限定场景的真实 Obsidian 复核**。旧草稿、确认后的编辑和重载恢复均停止覆盖并保留新增正文；普通合并仍能完成。修复已构建到开发目录 `main.js`，日常库的包与原工作台完整联动尚未验证。

五种类型的合并成文质量、优化前后对照及独立留出结果另见[合并质量实测](MERGE_QUALITY.md)。该报告有独立材料与真实请求记录，不并入下述九次基线统计。

独立核对依据为 [SciPy butter](https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.butter.html) 与 [NumPy fftfreq](https://numpy.org/doc/stable/reference/generated/numpy.fft.fftfreq.html)。本轮没有核查真实 RF 器件数据。

**来源覆盖仍有限制。** 三次启用联网的核查，各有一条完成的原生 `web_search_call` 记录：前两次打开 SciPy 页面，来源错配案例打开 NumPy 页面。报告中还引用了其他对应页面，但返回记录没有提供逐一访问这些页面的完整证据。技术判断与引用页面内容由本轮另行核对；不能仅凭报告有链接就认定模型逐条完成了外部核验。

## 合并的数据保护验收

修复前，公开 `confirmMerge` 在两种真实场景下返回完成但丢失新增正文：首次日志保存暂停期间编辑主笔记；草稿快照生成后、确认前编辑主笔记。原始前后文本保存在基线结果文件的 `mergeRace` 和 `staleDraft` 中。

修复后，真实 Vault 中分别确认：主笔记确认前编辑、冗余笔记确认前编辑、主笔记在首次日志写入期间编辑，均返回 `E321_MERGE_CONTENT_CHANGED`。被编辑文件全文保持一致，两篇源笔记仍存在。确认后的冲突保存恢复记录；重建服务、读取该记录并继续恢复，仍拒绝覆盖且全文不变。

单元回归另外验证了原子回调入口处的编辑、引用笔记写入期间的编辑、检查点保存失败后的等价恢复、恢复前的新编辑，以及旧版本保存的快照与草稿不一致的记录。已将并发编辑策略写入[产品需求](REQUIREMENTS.md#索引与合并)，实现见[运行设计](DESIGN.md#合并提交与内容保护)。持久化格式未升级。

合并对话框的组件测试确认：冲突后保留编辑内容，显示“笔记已修改，合并已停止”，重新生成按钮仍可用，不自动请求模型。未声称已测试原工作台的真实鼠标交互，或提供跨文件事务与回滚。

## 复现与已完成检查

模型测试入口是 [feature_eval.mjs](../scripts/feature_eval.mjs)。通过进程环境变量 `CR_TEST_API_KEY` 注入临时密钥；不放入文件、命令参数中的模型配置或插件设置。运行全部材料：

```sh
node scripts/feature_eval.mjs
```

也可在命令后列出 case id，例如 `verify_errors merge_conflict cards_dense`。默认输出到 `tmp/feature_eval/results.json`；`CR_EVAL_OUTPUT` 可指定其他结果文件。模型调用前须取得授权；本次临时密钥不随成果保留。

宿主工具是 [feature_host_eval.ts](../scripts/feature_host_eval.ts)。用 esbuild 打包为 CommonJS，`obsidian` 保留 external；在开发库 Obsidian CLI 的 `eval` 上下文中加载。CLI 的 Node require 不提供 obsidian 模块，本轮桥接的是新建测试文件的真实 TFile 构造器。`run(app, corpus, records)` 执行普通提交；`runMergeRace(app, records)` 验证确认后窗口，第三参数 `before_confirmation` 或 `before_confirmation_redundant` 验证旧草稿；同时检查拒绝结果、源文件全文和重载恢复。既有同名测试文件会显式报错，不覆盖。
