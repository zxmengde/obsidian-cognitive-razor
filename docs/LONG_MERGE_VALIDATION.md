# 长文合并实测

结论：当前版本在本轮结构化长文中表现良好。两篇合计约 1.3 万、2.8 万、4.8 万字符的材料，未发现检查范围内的配置、数值字段、单位、来源或文末例外遗漏。另测的一组连续论证保留了推导与结论范围。实际遇到一次上游过载，插件将其识别为失败，没有返回可确认草稿；单独重测成功。

本轮没有修改生产代码或提示词，测试的是 `072a436` 的合并行为。所有材料为合成教学内容，不含用户既有笔记，也不是实际实验数据。

## 内容结果

下表使用消除测试材料指代歧义后的对照版。字符数包含中文、数字、英文和 Markdown，均为两篇正文合计，**不是单篇中文字数**。

| 类型 | 两篇输入字符 | 生成正文字符 | 独有配置 | 检查结果 |
| --- | ---: | ---: | ---: | --- |
| 实体：数据包 | 12,651 | 3,973 | 40 | 两个数值字段及单位、来源、条件与文末例外保留 |
| 议题：归档裁决 | 27,648 | 6,311 | 90 | 同上；附件完整性分歧在正文及 conflicts 中保留 |
| 机制：状态机 | 47,629 | 9,385 | 157 | 同上；故障优先、连续计数、人工复位且无故障等条件保留 |
| 机制：相同输入再生成 | 47,629 | 9,426 | 同一批 157 | 数值、条件与例外保持，措辞有正常变化 |
| 连续论证：局部拟合判读 | 6,148 | 5,437 | 无配置编号提示 | 18 项预设语义检查未发现关键内容丢失 |

三个不同材料共定义 **287 个配置、574 个有标签和单位的数值字段**。重复请求不增加独有配置数。脚本检查了全部配置编号、局部数值对、表格标签与单位、来源链接、固定标题顺序及元数据并集，均未出现待复核缺项；同时直接对照了八类公共规则、每档预先选定的 24 个记录，以及各自独有的正文信息、分歧和文末条件。语义评阅由开发代理完成，不是独立人工评审，不能据此给出通用正确率。

结构化材料主要通过“公共规则说明＋每配置一行表格”压缩。当前值与历史建议值、模式甲与模式乙、原始点数与有效点数均保留不同角色，未统一成一个数值。所有行只适用于对应配置，未把局部例外推广成通用规则。输出缩短本身没有被当作成功标准。

连续论证额外检查了几种容易被简写改错的关系：

- 半功率宽度为 `2g`，半幅度宽度为 `2√3g`，两者阈值不同，没有被判为相互矛盾。
- `A` 与 `Ae^{jθ}` 的幅度等价，只用于说明复振幅相位不能唯一恢复，没有扩大成所有参数都不可辨识。
- 训练残差 `0.020→0.012` 与留出误差 `0.025→0.031` 的归属和方向保留，没有补统计显著性或自行加权。
- 建模者、测试工程师、负责人的观点仍有归属；任务门槛没有变成行业标准。
- `run-Q` 的补测分歧保持未决；文末“靛青支路”的局部限制和源摘要、人工确认双条件均保留。

可直接阅读未经编辑的[最大档生成稿](../evals/long_merge_example.md)和[连续论证生成稿](../evals/long_merge_narrative_example.md)，自行判断成文质量。

## 初轮材料歧义与失败记录

初轮三档材料由同一生成器构造：补充稿交换了数值字段的列举顺序，却继续使用“前一个数量描述扫描网格，后一个数量描述剔除后的集合”。这会使指代与字段名称不一致。模型在三档中都保留了数值字段，同时指出这一实际歧义，不能算作模型误报。

初轮输入长度为 12,665、27,680、47,685 字符，输出为 4,889、6,872、10,970 字符；检查同样没有发现配置、数值字段、单位、来源或尾部标记缺项。原材料和三次原始结果完整保留。随后只把该句改成明确的“原始点数／有效点数”，数值、编号、其他规则、代码和提示词保持不变，另生成对照版。没有用对照版覆盖初轮，也没有把材料修正称作插件修复。

连续论证首次请求在 130.8 秒后收到 SSE `error`：`server_is_overloaded`。虽然 HTTP 状态为 200，生产执行器仍返回 `E208_PROVIDER_STREAM_FAILED`，没有返回完整草稿，也没有自动重试。待其他请求完成后，以相同输入、模型和参数单独手动重测一次，161.4 秒后成功。原失败流和未知用量均保留，没有把半截输出拼成成功结果。

## 模型、用量与复现

测试日期 2026-10-26。用户指定 `http://39.105.206.63:8317/v1`，Responses API，`gpt-6.1-sol`，high 思考等级。请求和响应的 model 字段一致；这不是对转发服务背后模型的独立身份认证。沿用生产提示词、请求组装、Node HTTP 流传输、解析和合并执行器；没有搜索、自动重试、种子或模型回退。最多两个独立请求重叠，耗时不能当作固定性能保证。

共 9 次真实请求：三档初轮、三档对照、最大档重复，以及论证失败和单独补测。8 次返回完整草稿，1 次明确失败；样本太少，不估计服务失败率。完整草稿请求耗时约 115–238 秒。8 次报告用量的请求合计输入 167,514、输出 43,097，合计 210,611 tokens，缓存读取 39,424。失败请求未报告用量，不表示零费用，也没有据此计算账单。
