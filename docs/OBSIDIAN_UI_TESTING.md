# Obsidian 验收

## 环境与重载

使用原开发库的明确测试笔记进行业务验收。代码库路径为 `C:/CODE/obsidian`，插件 ID 为 `cognitive-razor`。向日常库同步时只处理已列明的插件程序、模板与必要运行格式，不读取既有笔记或凭据，不覆盖个人设置及模板定制。

先用 Obsidian CLI 核对目标库、插件版本、活动任务和错误基线。仅在没有 pending 或 running 任务时重载；版本变更时重新加载插件 manifests。CLI 不可用时先确认应用位置和进程；重试应基于环境变化。

真实界面操作优先使用已安装的 Obsidian CLI；需要鼠标键盘时使用可用的 Computer Use 工具。只读 DOM 用于核对界面，不代替用户输入测试。

## 场景

| 场景 | 操作与检查 |
| --- | --- |
| 启动 | 打开工作台并再次执行，确认聚焦同一视图、运行时就绪 |
| 输入 | 在没有原草稿时输入测试概念并清空，检查按钮与文本状态 |
| 队列 | 切换筛选、展开与收起，确认计数和状态一致并恢复原筛选 |
| 设置 | 切换 AI 服务、工作流、备份页，核对键盘与独立窗口操作 |
| 创建 | 对获准测试概念执行定义、确认类型、等待各阶段，核对队列与实际文件 |
| 分类和链接 | 核对多标准分组、父项范围、简明名称及标准化创建得到的目标路径 |
| 核查 | 核对报告标记、正文保留、美元公式定界符与状态更新 |
| 卡片 | 核对镜像目标、整批追加、已有内容保留、Decks 展示及中断行为 |
| 索引和合并 | 核对向量、候选、合并预览、确认写入与回收站行为 |
| 重载恢复 | 检查阶段本地提交、任务终态及没有未经确认的新模型请求 |

## 证据

记录应用版本、插件版本、协议、模型与测试数据。分别标明单元测试、离线传输截获、真实宿主加载及真实模型业务链路。仅加载插件不能证明生成质量或全部交互已通过。

工作台根节点为 `.cr-workbench-root`，队列为 `.cr-queue-section`，任务行为 `.cr-task-item`，设置为 `.cr-settings-root`。设置可能位于独立窗口，主窗口查不到节点时先核对窗口。

测试结束检查新增错误、任务数和实际文件结果；恢复筛选及草稿等界面状态。测试材料放在项目 tmp/，交付前清理；报告中只保留必要证据。
