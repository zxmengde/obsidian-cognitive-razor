# Cognitive Razor 真实界面验收

直接使用 `computer-use:computer-use` 技能进行 Windows 鼠标键盘操作，使用项目的 `obsidian-cli` 技能诊断。按当前技能目录读取 Computer Use 文档，发现实际可调用的工具并验证窗口控制，无需额外的界面测试技能。

## 环境检查

本机代码所在库为 `obsidian`，路径 `C:/CODE/obsidian`，插件 ID 为 `cognitive-razor`。业务验收在专用测试库执行，先确认其名称、路径和加载的插件版本。

```text
obsidian help
obsidian version
obsidian vault=<测试库名称> vault info=path
obsidian vault=<测试库名称> plugin id=cognitive-razor
obsidian vault=<测试库名称> dev:errors
```

以上检查只确认运行环境，不证明用户流程通过。CLI 连接失败时继续通过 Computer Use 检查实际窗口并排障。错误缓冲区非空时对照测试前后基线，不能把历史错误归因于本次操作。

## 核对与修复

- 当前工作台根节点：`.cr-workbench-root`；队列：`.cr-queue-section`；列表行：`.cr-task-item`。只读 DOM 查询用于核对结果，不代替真实输入。
- 设置根节点：`.cr-settings-root`，可能位于独立窗口的文档中。主窗口 `document.querySelector` 返回空值不能作为失败依据。
- 单测：`npm test -- <相关测试路径>`。按变更执行 `npm run check`、`npm run check:test`、`npm run build`。
- 确认目标测试库及任务队列无活动任务后，才能在需要时执行 `obsidian vault=<测试库名称> plugin:reload id=cognitive-razor`，然后重走原 UI 路径。
- 当前工作区有其他开发改动。不得重置或覆盖；构建会生成整个当前工作区版本，重载前应说明这一影响。
