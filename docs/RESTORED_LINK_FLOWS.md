# 已授权链接流程修复重建

## 来源与边界

本次从恢复基线 `5931bfbfdedca6fb607a2d66d1e5982fdec78811` 重新实现已授权的链接修复。历史 `1665aba` 的 Git 对象不在当前恢复包中，本次不是复原其 commit hash，也不沿用历史测试结果。未引入被拒绝的命中统计 UI。

修改只涉及已有生成、拓展和人工合并流程：不改变人工阅读两篇笔记后决定是否合并的流程，不添加自动合并、反向补链、模型迁移或批量重生成。

## 修复

- 合并预览合并两篇来源笔记的 `parents` 与模型草稿的 `parents`，归一化去重。确认时只提交用户编辑后的列表，包括删除部分父链接或清空列表。
- 结构化章节按目标类型目录生成明确路径链接，显示文本保留概念名称。同名实体和机制不再生成相同的裸链接。
- 层级拓展解析路径、别名、标题锚点和 `.md` 后缀，保留已存在或已合并笔记（含库根目录）的完整路径。带别名或 `.md` 的明确路径在配置改变后仍可展开；未标明的未知目录和路径穿越不作为新建目标。去重以类型和目标路径为准。
- 层级和抽象拓展的父链接使用来源笔记的实际路径，不依赖可能重复的显示名称。
- 合并对话框仍使用原来的两个“打开笔记”入口，但点击时按 CRUID 获取最新路径。缺失时显示错误，不以同名文件替代。
- `parents` 编辑框只按换行拆分，标题内逗号不会拆成两个链接。
- 新 Create artifact 在确认时保存目录方案快照；渲染和中断重放使用同一个快照。可选字段保持 `7.0.0` 兼容，缺少字段的旧 artifact 继续使用旧裸链接渲染，避免恢复时改变已写入的正文。
