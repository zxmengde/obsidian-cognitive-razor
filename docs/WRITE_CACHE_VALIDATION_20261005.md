# Write 请求、模型参数与结构分类验证（v8）

本轮使用固定云端 Obsidian、公开知识合成输入及现有反代。真实请求串行逐笔执行，无自动重试，没有发送个人笔记或改动原设置和队列。模型输出由真实阶段 Validator 校验；测试夹具没有写入来源笔记。源码候选的发布和本地安装状态以发布记录为准。

## 修复内容

- 日志区分请求模型与响应报告模型、申请缓存参数与响应报告参数。缺少用量保留未知；合法的 0 保留 0，非法数值另列。响应回显不能证明上游账户、缓存策略或账单实际应用。
- 两个 OpenAI 协议、任务解析和参数摘要共用采样生效规则。精确 `gpt-6.1-sol` 默认推理以及显式激活的推理不发送 temperature/top_p；保存的配置仍保留，摘要说明未发送，日志从实际构造的请求体记录发送值。留空 effort 不被擅自补成 medium；未知别名和日期型号不猜默认能力。
- 精确 `gpt-6.1-sol` 的 none/minimal 在发送前拒绝；同一判定也进入参数摘要，避免显示成可实际发送的有效配置。不会自动替换 effort 或重新收费请求。
- 三个结构阶段使用同一 157 字符任务：主干覆盖优先，层级项使用清楚一致的划分依据、直接下一层和最小必要重叠；有实质区别的重要范围保留并说明交叉。没有数量目标或学科特例。公共 system 仍 444 字符；其余 11 阶段的解释深度、全部 Schema 和严格字段约束不变。v8 隔离旧版本历史，已验证的草稿和来源仍保留。

## 真实调用证据与边界

夜间共 11 次传输：9 次成功，1 次 HTTP 400，1 次 HTTP 502。没有自动重试。成功响应已报告的总用量为 35,432 tokens；两次失败未取得用量，不能当成免费或 0。测试申请的输出限制不等于上游实际执行该限制的证明。

| 对照 | 观察 | 可以得出的结论 |
|---|---|---|
| v8 统计学两次完全相同请求，紧邻发送 | 第二次 input=1496，cached=1408，首笔 cached=0；两体 SHA256 相同 | 该次隐式缓存精确重复观察到复用 |
| 原客户端文本历史追加，同 Schema/key/model | input=3573，cached=0；距原正命中约 55 分钟，string input 转消息数组 | 记录此路径结果；时间、账户与渲染差异未知，不能归因客户端或跨阶段能力 |
| domain/issue/theory 的 v7/v8 公开样本 | 严格结构均有效，主干基本保留 | 支持本次输出可用；单次样本不证明所有维度提高 |

质量审查保留的限制：v8 议题样本中介/路径效应解释变薄；统计学高维与依赖问题合并偏杂；理论的误差更新/线索竞争紧耦合，速率估计的归属还受原输入范围歧义影响。没有用条目更少作为质量标准，也没有挑选缓存重复输出替代预先指定的主样本。

各 Write 阶段的严格 Schema 本来不同，会影响渲染前缀；相同 system 或 cache key 不保证跨阶段命中。本次没有放宽 Schema。反代是否原样支持 explicit/TTL/断点未实证，缓存字段可能经过代理转换；本轮不更改个人缓存设置，也不能据此计算实际账单节省率。

## 安全更新模板

维护源码为 `scripts/update-write-defaults.mjs`；默认只检查：

```sh
node scripts/update-write-defaults.mjs --plugin-dir "/path/to/cognitive-razor"
```

安装前停止插件和外部模板编辑，确认无活动任务。检查通过后，用已有且合法可写的少量模板回退位置执行：

```sh
node scripts/update-write-defaults.mjs --plugin-dir "/path/to/cognitive-razor" --rollback-dir "/path/to/release-sync" --apply
```

从已逐字节确认的历史 v5 或 v6 默认需要 14 阶段文件及 write-policy，共 15 个；已知 v7 默认只更新三份 structure。四个旧 base 也参与预检。任一未知定制整批拒绝，不能覆盖个人规则；权限失败应停止，工具不会修改 ACL。新 runtime/PromptManager 才读取新磁盘模板，版本号不会自动刷新旧内存缓存。

全部 19 项会在预检后复查，暂存后还会复读目标和队列；仅接受普通、字节匹配的备份，拒绝符号链接与相互矛盾的缺失标记。普通 rename 不提供 compare-and-swap，多文件不是整体事务，中途 I/O 失败应使用已保留原字节恢复。

源码检查：完整类型/Svelte、测试类型、lint、全部业务测试与构建；另有合成临时目录的 CLI 测试、独立采样矩阵及真实宿主 API0 参数摘要验证。真实宿主验证后的正式插件与原队列恢复须以收尾核对记录为准。

历史兼容清单额外列入了 88ec8932 版本三份结构模板的精确 SHA256。云库 18 份原文件与该历史版本的原字节逐项匹配，write-policy 按该版确实缺失。未知旧版本、任何自定义字节仍拒绝，不能仅凭“版本较旧”放宽检查。
