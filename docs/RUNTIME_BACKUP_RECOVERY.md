# 运行数据备份与恢复

## 保护范围

设置页的“备份并重置运行数据”备份插件设置及插件目录 data/，排除其中的 backups/，随后重置设置与运行态。

包含队列、工作流、向量、重复对及其他运行文件。不包含知识库 Markdown、卡片、附件、插件程序或提示词。保留正文不等于备份正文；笔记与卡片须使用独立库备份。

普通设置导出去掉 API Key。重置快照中的 settings.json 可能包含密钥，只能作为本地私密文件保存，不分享或上传。

## 快照布局

`data/backups/reset-<时间>-<唯一标识>/` 包含 settings.json、manifest.json 和 runtime/。manifest 列出运行文件完整相对路径，runtime/ 保存对应副本。

复制并逐文件回读校验完成后才删除原件。复制失败时保留原运行数据；缺少有效完整清单的目录不用于恢复。每次操作使用独立目录。

## 中断恢复

删除原件前写入 data/reset-in-progress.json。删除失败立即尝试回滚；进程退出后在下一次启动运行服务前恢复。恢复先于队列、工作流、向量、模型服务和普通临时文件清理。

恢复失败时保留快照和标记并停止运行服务。修复存储问题后重载，不删除标记绕过恢复。结果未知的请求保持 interrupted；正常 pending 任务遵循队列规则。

最终删除标记若已提交而存储仍报错，程序核对实际状态；无法确认时报告结果不确定。

## 人工恢复

没有一键恢复按钮。需要恢复时：

1. 禁用插件，另存当前设置与 data/，保留备份。
2. 核对同一快照的 manifest 与 runtime 完整性，将 runtime 的完整文件集恢复到 data/；保留 data/backups/，避免混入其他批次状态。
3. 将同一快照的 settings.json 作为插件 data.json 恢复，按私密文件处理。
4. 启用前检查 data/queue-state.json 的 paused 状态。恢复的 pending 请求可能继续运行；需暂停时仅修改根级 paused 为 true。
5. 启用插件，核对设置、队列、工作流及路径，再决定恢复运行。

人工恢复不还原正文与卡片。运行快照与当前笔记不一致时，提交保护可能拒绝继续；应核对实际文件，不强改任务状态。

程序与运行数据应成套恢复。含 reset-in-progress.json 的状态先完成恢复，再替换程序，避免加载不完整运行态。
