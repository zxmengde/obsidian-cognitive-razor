# 运行数据备份与恢复

## 保护范围

“备份并重置运行数据”只备份插件设置和插件目录下的 `data/` 运行数据（排除历史 `data/backups/`），随后重置设置与运行态。

- 包含：设置快照、队列、工作流、向量、重复项、插件运行日志等当时存在的运行文件
- 不包含：知识库 Markdown 正文、卡片、附件、插件程序和提示词文件
- 重置不会删除 Markdown 正文或卡片；“保留”不代表已备份，不能回滚生成、核查或合并造成的正文变化
- 普通“导出设置”去掉 API Key；重置产生的本地 `settings.json` 可能包含 API Key，请保密，不要分享或上传

## 新备份布局

插件目录 `data/backups/reset-<时间>-<唯一标识>/` 包含：

- `settings.json`：重置前设置
- `manifest.json`：运行文件完整相对路径清单
- `runtime/`：原 `data/` 文件副本，例如 `runtime/queue-state-v5.json` 和 `runtime/workflows/...`

复制并逐文件回读校验完成后才开始删除原文件。复制失败可能留下不完整备份目录，但原运行数据不删除；不要从缺少有效完整清单的目录恢复。重试使用独立目录，不覆盖旧快照。旧版备份的文件直接放在备份目录，不含 runtime/ 和清单，本次不迁移或改写它们。

## 中断自动恢复

删除原件前写入 `data/reset-in-progress.json`。删除失败立即尝试完整回滚；进程崩溃则在下次启动运行服务前恢复。

恢复在队列、工作流、向量、模型服务以及普通 `.tmp`/`.bak` 清理前执行。恢复完整后沿用原有原子写入恢复规则。结果未知任务保持 interrupted，不当作缺失任务重发；正常 pending 任务仍遵循原队列规则。

若恢复失败，保留备份和标记，停止启动运行服务。修复存储问题后重载。不要直接删除标记来绕过保护；标记损坏时，保留原文件与完整快照，先检查对应清单。

最终删除标记可能已提交而适配器仍报错：确认标记已不存在则按重置成功处理；无法确认时明确报告结果不确定，不假称已经回滚。

## 成功重置后的人工恢复

没有一键恢复按钮。确需恢复时：

1. 禁用插件，另存当前插件 `data.json` 和 `data/`，保留历史备份；不要在运行中替换状态
2. 核对同一备份的 manifest 与 runtime 完整性，将 runtime 恢复为插件 data/ 的完整运行文件集，不混入重置后的新状态，不单独恢复队列或工作流；保留 data/backups/，不要递归复制历史备份
3. 同一备份的 settings.json 对应插件设置文件 data.json，按含密钥的私密文件处理
4. 恢复队列可能继续 pending 请求并收费。启用前检查 queue-state-v5.json；需先人工检查时，仅将根级 paused 设为 true，不改任务状态或标识。不确定格式时不要继续恢复
5. 启用插件，核对设置、暂停状态、队列与笔记路径，再决定是否恢复运行

此流程只还原设置/运行态。正文和卡片必须依靠独立笔记库备份。旧运行态与当前笔记不一致时，快照冲突保护可能拒绝继续；不要强改任务状态绕过。

## 程序回滚

代码回滚不等于数据/正文回滚。若新版留下 reset-in-progress.json，应先让新版完成恢复，再回滚程序，避免旧版本不识别标记而加载半套运行态。
